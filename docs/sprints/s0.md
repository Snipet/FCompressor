**Manifest format** (03 §4.2; read by `Scripts/sprint/ownership.py docs/sprints/s0.md#<ID> <worktree>`):
- Each manifest is one fenced `text` block under a `## <ID>` heading; its first line is `TASK <ID> …`. IDs: `G1`,
  `F0`, `B0` (the card codes; `S0.1`–`S0.3` are the card numbers).
- A field starts at column 0 with an upper-case keyword (`TASK GOAL OWNS FROZEN FUNKGUI PRESETS DONE READS INPUTS
  DELIVERABLES NOTES`); lines that start with spaces continue the previous field.
- `OWNS` is a whitespace-separated list of globs, relative to the root of the task's repository, copied verbatim from
  the card: `*` matches within one path segment, `**` any depth, `{a,b}` alternatives. Paths under `.claude/` are
  ignored. Every other field is prose for the agent and the lead.
- Standard command tags (`[FG]`, `[DSP]`, `[AGENT]`, `[OWN]`) are SPRINTS §0.2; `$WT`/`$FWT` are written literally.

## Lead revisions at the S0 base (2026-09-22, after the pre-work handoffs)

1. **Header checks use `-x c++-header`, not `-x c++`.** With `-Werror`, compiling a `#pragma once` header as a plain
   TU fails on `-Wpragma-once-outside-header` (found by S0.L3). F0's DONE above is patched; B0's
   `Scripts/check-headers.sh` and G1's `tools/check-headers.sh` must use `-x c++-header` (or `-x objective-c++-header`
   for `.h` files that need ObjC).
2. **G1 owns `tools/legacy/**`** (added to its OWNS above).
3. **Harness v2 additions G1 must make** (G1 owns `Harness.h`; list them in the handoff; additions only):
   - a way for a probe to add extra fields to its results JSON (03 §3.2.5: `dsp.registry` reports provisional keys),
     e.g. `void note(std::string_view key, std::string_view jsonValue)`;
   - `setEnv`/`unsetEnv` test helpers (HR's harness had them; the ported PrefsCheck needs them), and make
     `funkgui::env()` either uncached or re-readable in tests so set-then-read works;
   - v0.0.1 also added `harnessError(why)` (exit 4) beyond 03 §3.2.1 — keep it.
   - G0 made ObjC class names `FUNKGUI_OBJC_NAME(RenderView)` / `FUNKGUI_OBJC_NAME(DisplayLinkTarget)`; G1 defines
     that macro (and the other seams) in `include/funkgui/core/Config.h`.
4. **Machine constraints (all cards).** The data volume has **≈ 5.8 GB free**, and the machine is heavily loaded by
   other work (load average 500–800), so builds run several times slower than the design's estimates.
   - Check `df -h /System/Volumes/Data` before each configure. If less than **1.5 GB** would remain, stop and report.
   - Keep at most two build directories alive at once; delete a build directory as soon as its acceptance result is
     recorded in your handoff (record configure/build times first). Never build the `lead`, `universal` or sanitizer
     presets.
   - Build with `-j6` at most (`cmake --build ... -j 6`, `CMAKE_BUILD_PARALLEL_LEVEL=6`).
5. **Pins and tools from the cache** (S0.L2 handoff): `~/audio/.deps/JUCE-8.0.4`, `~/audio/.deps/bgfx.cmake-v1.153.9385-561`,
   `~/audio/.deps/tools/shaderc-v1.153.9385-561/shaderc` whose `shaderc.stamp` first line is exactly
   `bgfx.cmake 99752df38e40179cf998bb880fe4c16c0b3d60ca`, and `~/audio/.deps/tools/pluginval-v1.0.4/pluginval`
